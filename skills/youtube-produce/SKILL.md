# 观点视频制作总控

默认制作思路：自然口播主导，实拍或照片建立情境，持续存在的对象解释变化，少量短句收住观点。先把“什么对象发生了什么变化”讲清楚，再决定素材和动画。保留有用的摄影拼贴，不默认每段一页，不以素材数量、特效数量或固定换镜频率衡量完成度。

在本仓库根目录运行 `youtube-studio`，生产源码位于 `src/youtube_studio/`。已停用的旧 skills 和运行时已清理。

正式作品在同级 `youtube/episodes/<ID>`；试剪样片在 `youtube-workbench/examples/<ID>`。文中的 `build/`、`.cache/`、`state.json` 和 `.run.lock` 均相对工作台 `runtime/episodes/<ID>/`（样片使用 `runtime/examples/<ID>/`）；`deliverables/` 相对剧集根。 跨库迁移以同一份缓存和正式成片哈希验证，不通过重新生成来验证路径。

## 工作方式

研究来源与制作职责：投资思想、经验和公司研究按 [trade 研究交接](../youtube-write/references/trade-context.md) 只读选取；本期选题由用户请求确定。仅要求修改技能时停留在技能与文档层，不自行拿历史公司、新主题或样片测试。

1. 对新剧集执行 `init --episode <目录> --title <标题>`。已有 `config.json` 时读 `brief.json`、`script.json`、`config.json` 和 `status`，接续已有工作。
2. 需要研究或改稿，使用同级 [youtube-write](../youtube-write/SKILL.md)。先将本期采用的作者立场、真实经历、证据与未知项交给写作，再形成观众问题和论证。稿件和分镜以 `script.json` 为唯一可编辑源；`build/script.md` 只是阅读副本。不要把旧 aligned 文件当原稿。先明确对象、动作、结果和论证条件；语义单元边界不要求换画面。
3. 用 [youtube-visuals](../youtube-visuals/SKILL.md) 确定对象如何持续、变化、落定，再匹配当前模板；新主题不强套街区示例。配音问题使用 [youtube-voice](../youtube-voice/SKILL.md)。依赖、数据格式和 provider 配置见 [运行契约](references/runtime.md)。
4. 缺少图片、实拍视频、音乐或音效时，先使用 [youtube-media](../youtube-media/SKILL.md) 做素材准备。图片、footage 视频和单元 audio_tracks 可按契约回填；素材到位后仍需编排和实际导出验证。音效绑定具体动作，BGM 可省略，BPM 仅在节拍确有用途时处理。
5. 执行 `doctor --episode <目录>`，依据缺失能力修复。doctor 不验证外部账号权限；实际服务请求也必须检查。默认按“脚本与配音确认 → 浏览器看全片 → 人工提修改 → 只预览改动片段 → 更新正式镜头 → 快速合成与验收”执行。`preview` 生成并检查编排后启动浏览器；改动后用 `sample --shot <ID>` 或 `sample --start <秒> --end <秒>`，最后 `run`/`resume` 更新失效片段并合成。命令、缓存边界与人工确认方式见 [快速预览指南](../../docs/guides/fast-review-workflow.md)。已授权完整出片时可连续执行；不把preview或prepare当正式交付。
6. 检查 `deliverables/qa.json`、实际 MP4 抽帧和成片，重点看实拍是否正常运动、原对象是否意外重置、分流/复制方向是否清晰、运动中文字是否碰撞、音画含义是否一致。机器通过不等于事实已经核实或视觉已经人工审阅。报告实际检查范围、未完成项和可播放文件。

新风格或大幅改版先用一个完整论证选段验证，原剧集保留。时长服务于论证，不为凑时长机械截句。验收三件事：只听声音能否理解、画面是否增加理解、修改观点或配图是否可局部重生成。没有用户要求时不反复重做样片。

用户要求参考某作者或明确拒绝当前风格时，执行 [参考风格对照](references/reference-style-review.md)：比较承担同一任务的实际片段，追查计划是否进入配音请求与渲染实现，再更新对应制作环节。用户已拒绝的声音、视觉记录为本版失败，不能只改技能文字后宣称样片已改善。

用户要求约90秒样片时，放在 examples 的独立目录，保留来源剧集及压缩选段说明。样片应包含主张、一个完整推演、必要前提和收束，不默认截取全片前90秒。先生成实际旁白再测时长；不靠尾部静音、截断句子或伪造时间戳凑数。沿用已明确获准的用户音色和偏好，授权或可用性不足时才询问。样片没有真人或暂未配乐时说明这一风格验证范围，不能据此宣称全面还原参考片。

从已认可的样片扩展完整篇时，将正式版本放入 episodes，记录样片来源并保留原文件。先用样片实测语速估计稿件长度，删减重复论证，再以完整旁白实测时长校准；不要为压时长加快已认可的语速。沿用已批准且仍适合本期的音色、封面、品牌素材和缓存，新增内容单独生成；旧长稿中的占位真人镜头必须替换或落实。短样片的验收结论不能覆盖新增章节、全片音乐和导航。

进入配音前完成写作技能中的来源与立场检查；缺关键证据时先处理对应缺口，不先批量配音。内容变动返回受影响的单元，正常已授权步骤连续推进。此处是 Agent 的执行责任，不是新增程序闸门或自动同步能力；参考分析报告中的开发计划也不能当成现有功能。

交接材料：`editorial-review.json`（论证与人工待审项）、`voice-review.json`（录音识别差异）、`storyboard.md`（实测镜头与解释任务）、`qa.json`（实际导出机器检查）。前三项由当前输入生成到 build，正式导出的 qa.json 写入 deliverables；preview 导出写入 build/preview。素材任务另交 media-plan.json、media/manifest.json、media-review.md；添加音轨时核对 build/audio-mix.json。人工抽帧、连续播放与听审结果分开保存到 review.json，绑定本次 MP4 哈希，不能让自动重跑抹掉人工结论。

## 执行规则

- 用户已要求自动出片时，在授权范围内连续完成正常步骤，不重新逐环索要确认。不要上传或发布；本 skill 的交付终点是本地成片。
- 不缺省替换音色，不用静音或空背景冒充正式成片。`--mode preview` 只允许明确的预览能力（如 macOS say），画面会标注制作预览。
- `--through compose` 可在无渲染的情况下生成完整时间线与可检查 HTML。不是成片完成。
- 缓存使用内容和真实媒体哈希；局部改图不重做配音。不要为恢复任务清空缓存。
- 未知结果的外部请求会进入 uncertain。先核查服务任务/账单，再决定是否用 `--retry-uncertain`；不循环盲目重发。配置和日志不得含明文密钥。
- 未经用户要求不批量改写历史剧集内容，不删除原始素材，不自动提交 Git。

仅请求技能整理、建议或复盘时只交付对应结果，不自动启动下载、配音和重渲染。连续街区只是已验证的专用模板；素材搜索仍由 agent 执行，不声称 run 已具备无人值守在线选材能力。

## 阶段完成标准与返工

投资观点片开头用独立 overlay 展示免责声明，正文不加句末句号；可断为两行短框，不把长句硬塞成长条。默认慢淡入约 1 秒、完全可见停留 1 秒、淡出约 0.65 秒；hold 指完全可见时长，duration 是入场、停留和退场之和。设置 offset 和 clear_before_cut，按实际第一个镜头边界验证，退场结束至少早 0.2 秒，不能只按口播 unit 结束时间检查。不写入任何口播 text。独立封面海报排除 overlays 和 captions，保留照片、标题与真实 logo；不能从带声明的 MP4 随便截一帧充当封面。只改声明时复用已确认原始语音；如同时去爆音，分别记录原母带与修复母带哈希。

收到观看体验反馈后，先连续检查问题前后的完整句群，再做帧级定位。记录进入、解释、重点改变、退场分别对应的声音；不能只在动作中点截图后宣布转场已修好。对于反复出现的例子，检查每次回访是否有新解释任务；发现长时间只有相同图解、旧问题常驻、材料整页突现，修改后以实际 MP4 顺序帧和连续片段复核。交付明确连续检查区间及听审范围，不能让工程完成取代观众体验结论。

按 [质量与交接](references/quality.md) 分别检查内容、声音、画面、工程、效率。学习小A的可操作对象与问题推进，学习思维咖啡的完整意思、认知递进与有条件结论；成片不以动画数量或固定切镜频率打分。

运行 quality 查看机器证据与待人工检查项。verify 通过表示导出机器检查完成；只有绑定本版 MP4 和输入指纹的人工检查也完成，质量状态才可为 reviewed。待听审或待连续观看不得自动改成通过。

小改配图复用语音与对齐；口播改变重做相应语音和后续时间线；只改来源元数据也要重新检查证据用途。先用完整论证选段验证新能力，再推广整期；样片时长服务于论证，不固定为 30–45 秒。

## 片尾与声音修复交付

片尾先回收本期主题，把行动和必要条件随实际口播依次落下，最后留出有设计的频道落款和音乐收束；不能在最后一个词处硬切。无新录音时可使用已有末段口播加 2–8 秒无旁白落款，不虚构新配音或用空白补足时长。script.closing 显式指定 duration、tagline 和承接的 music_track；口播时间与成片时间分开保存，旁白只在落款时补静默，音乐延续并淡出。导航按口播章节的实际时长分配，落款出现时退出；不要让片尾延长改变原章节比例。

遇到咔哒、爆音，先按 youtube-voice 排查与处理。必须交付原始母带、修复记录和可核对的前后片段；机器检查合格不等于耳听无杂音。最终 QA 分开记录画面、音频指标和主观听审，未实际听审的项保持 pending。

## 剧集合并与上传素材

用户要求合并同一期的草稿、完整篇或导出平台上传素材时，使用 [合并与上传交付](references/upload-delivery.md)。保留一个正式生产根目录，旧阶段原件迁入工作台 episodes/<ID>/source/development 并记录指纹；上传包只包含当前成片及面向发布的素材。打包授权不等于上传或发布授权。

由完整片回做连续试剪时，要在独立样片中同时验证声音接续、信息出现次序、封面、片内章节和原版角标。帧检以导出的 MP4 为准；单独打开封面和不依赖外置网页的播放器复核。用户要求先看试剪时保留现有完整片。

收尾时按仓库 [AGENTS.md](../../AGENTS.md) 的“用户反馈与技能同步”条目检查本轮修改建议。跨剧集适用的验收规则同时写入仓库约定和对应技能，剧集记录保留本次选用的参数与实际复核结果。
