# trade → youtube：研究与作者表达交接

用于用户给出本期主题后，从 trade 取用相关思想、经验或研究。它是 Agent 工作约定，不新增 CLI、脚本 schema 或自动同步服务。

## 职责与入口

- trade 是既有投资思想、经验与研究判断的来源；youtube 还须围绕本期问题独立核验最新材料、比较解释并提出研究结论，再组织成观众问题、论证、口播和画面；raw 负责原始资料获取与证据核验。个人记录不能替代当前竞争研究，执行标准见 [独立研究与投资主张](investment-thesis.md)。
- 默认从 youtube 的兄弟目录 `../trade`、`../raw` 定位。先读来源仓库当前 `AGENTS.md` 和入口，不硬编码个人机器路径。目录不可用时说明缺项，继续使用用户已提供的材料，不假装已读取。
- 用户已明确自己的经历在 trade 中。需要个人来由、情绪、选择与教训时，主动检索 `02-复盘/` 及相关 `附录/`，读命中段落的上下文，不让用户重复讲述已有记录。先选与本题相关的一条经历，再核对日期和立场；只有材料确实未记录或存在影响表达的冲突时才补问。经历来源与真人录像是两件事，缺录像不等于缺个人经历。
- 只读取本期问题需要的文件和段落。公司研究从公司主页进入；公司路径按 raw 的 `config/companies.yaml` 中 `analysis_file` 定位，不按公司简称猜目录，也不把来源仓库的优先公司当作本期选题。
- 视频制作默认只读 trade/raw。个人知识体系、投资哲学、交易系统、检查清单、复盘、组合及其他个人沉淀不得顺带改写；问题和建议留在本期交接或对话中。公司研究或原始资料需要更新时，按该仓库技能与具体授权单独处理，不能由视频任务顺带执行。

## 判断材料属于哪一层

| 来源 | 本期可以怎样用 | 必须保留的区别 |
|---|---|---|
| 根目录投资哲学、交易系统、检查清单 | 说明作者已经采用的原则和约束 | 原则冲突列明，不自行选宽松版本；新表述不自动成为正式规则 |
| `00-思维框架/` | 提出研究问题、组织分析方法 | 方法不直接产生买卖条件、收益承诺或仓位限额 |
| `02-复盘/` | 讲当时的处境、选择、理由和后来的反思 | 历史判断按当时叙述，不伪造当时已知信息，不写成当前持仓 |
| `03-公司研究/` | 取当前论点、支持证据、反证、假设与待验证问题 | 当前结论与日期研究分开；研究解释不是原始事实，估值情景不是已实现结果 |
| `05-知识体系/` | 有归属的读书讨论、比较不同观点 | 不代表作者已接受，不支持公司结论或投资行动，也不与正式规则并列执行 |
| `04-投资组合/README.md` | 本期确需讨论个人约束时读取 | 默认不把完整账户、金额、数量或交易记录送入写稿模型或公开口播 |
| raw 的正式事实、原 PDF 与核验记录 | 支持事实和财务数值，保留口径 | 未核验数字不补写；推导值保留公式与输入引用 |

用户本轮的亲述也可作为经验与立场的来源，注明是本次陈述。它不自动覆盖正式文件；缺少日期或关键细节时保留不确定性，不补造交易经历。

## 交接给写作的最小材料

在已获授权制作的本期目录中，优先沿用现有策划记录；没有时可在 `source/planning/` 保存一份简短研究交接笔记。仅修改技能时不创建剧集、研究包或试点文件。

交接只保留会影响本期表达的信息：

- 本期主问题、研究截至日期，以及作者明确表达的立场。
- 可公开使用的真实经历；另标仅供理解背景的材料。避免把与论证无关的账户细节传入下游。
- 支持与反对关键主张的材料、解释链条、假设、未知项及失效条件。缺口注明影响哪一句，不要求无关研究全部完成才能写作。
- 来源类型、文件位置、版本或日期、相关段落与必要摘录；重要采用文件记录哈希。财报值保留原 PDF 路径、SHA-256、物理页码、表名/行名、期间、币种单位和口径。已有原始事实 ID 或计算快照时保留它们，不从旧 Markdown 表格补数。
- 来源 → 主张 → `unit.id` → `shot.id` 的对应关系；还未写稿时先记主张，写稿后补关联即可。

正文与分镜仍只维护 `script.json`。来源用现有 `sources`、`claims.source_ids`，推理和条件用 `argument`，作者立场与章节递进用 `narrative`。交接笔记保存依据和取舍，不复制一份独立可编辑正文，也不编造未实现的 `research_id`、自动场景返回等执行字段。

需要将来源文件作为 `asset` 使用时，按素材流程复制或截取到本期 `media/`，记录原文件、页码和裁切；不能把外部仓库路径直接填入受剧集根目录限制的素材字段。

## 从研究变成可听懂的表达

先选观众会遇到的一个困惑，再问哪些材料能解释它。取舍依据是有没有改变判断，不是覆盖 trade 的目录、书籍章节或全部公司指标。

允许把真实复盘整理成“当时为什么这样想 → 什么新事实提出挑战 → 现在保留或修正什么”。若记录没有显示作者改变立场，就保留为待讨论问题，不编成完成了认知转变的故事。个人经验能解释作者为什么关注问题，不能单独证明普遍规律。

用户要求把独立研究与个人感悟融合时，先找一条有原文依据、能贯穿本期的自问或矛盾，再把作者原则用于改变分析步骤：例如将对估值回归的期待转成不依赖倍数提升的回报检验，将护城河的边界转成业务分层，将现金流观转成再投入及股东回报核算。不能只在开头加一句“我认为”、插入几句投资名言，或按个人笔记顺序重新做资料流水账。以替换重复泛论为主，保持时长预算。

交接中分别列出作者原有判断、独立证据、二者的冲突与拟采用表达。带日期的“未受影响”等旧判断只能写为当时看法；经研究收窄的表述须标为本稿拟议判断，不假装作者早已完成这一转变。助手前稿的错误或改口不能直接移植成作者亲历。真实历史买入只叙述必要动机，不推断当前仍持有；默认去除账户金额、数量、仓位及旧目标价。投资原则不能替代当前报价与估值核验。

三类可组合的叙事方法见 [叙事规划](narrative.md)。从博主学习提问、因果推演与边界表达，作者的选择和经历来自实际材料；不要模仿口头禅或以虚构经历增强戏剧性。

## 配音前与后续更新

配音前由 Agent 检查关键来源和原句含义，尤其是事实/观点混写、调整值/实际值混写、当前/历史混写，以及数字、否定词和确定程度。财报数值缺原始依据时保留缺口，不靠画图、比喻或改成“个人认为”绕过核验。

再次制作或重新交付前，比较采用材料的日期、版本与必要哈希；变化只触发受影响主张复查，不自动证明结论改变，不自动覆盖作者观点。旧成片与旧研究时点保留，内容修正需要同步实际口播、字幕和画面。

融合返工须检查每个“我当时”“我曾经”“我一直”的事实依据；区分可公开节选和仅供理解的私密背景。保存来源到主张、单元及镜头的最小映射，交付时说明融入了哪些判断方式及保留了什么分歧。核对来源文件哈希未变；更新视频稿不回写个人记录。

这些检查由当前 Agent 执行并记录实际范围。CLI 的 `validate`、`review`、`quality` 各有现有职责，不会自动访问 trade、理解论证矛盾或认证全部事实。直接使用 text provider 前，应将已选择的公开节选和叙事要求写进本期 brief；链接到本文不等于模型已经读过材料。
