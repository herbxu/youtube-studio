# 观点递进与章节规划

先回答：观众带着什么认识来？哪一步让它不够用了？看完后应该会问什么？规划不是开场套路，也不是强制六章。

## 三种可组合的方法

- 机制问题：具体矛盾 → 观众直觉 → 反例/观察 → 可操作对象 → 条件下的判断。借鉴小A把抽象名词变成关系的做法，保留推导条件，不搬用夸张概率、投资收益或羞辱措辞。
- 行为问题：熟悉处境 → 自问 → 具体例子 → 换一个观察角度 → 适用边界。借鉴思维咖啡的渐进澄清和个人表达，删去没有改变判断的重复例子，不强制慢速或水彩风格。
- 判断变化：真实困惑 → 当时判断 → 有力反对意见或新证据 → 保留、修正或暂缓结论。借鉴一口新饭的问题链和核心模型反复推演；原判断与经历来自 trade 或用户亲述，没有立场转变记录时不虚构转变。

这些是写作方法，不是固定章节或片长。先按 [trade 研究交接](trade-context.md) 判断材料性质，再决定适合哪条叙事路径。核心图形可以在策划中反复被引用，但执行分镜必须符合当前场景契约；不能把叙事上的“回到这个问题”当成已经支持任意场景保存与返回。

一章结束时，指出已经解决什么、尚有什么疑问。结尾回收开头的问题，给出可使用的检查问题，不临时添加未经论证的结论。

## 已实现字段

script.json 可添加 narrative；新稿要求填写，历史稿保持兼容。章节是正文的分组，不另存第二份正文：

```json
{
  "narrative": {
    "audience_belief": "看到增发就认为一定吃亏",
    "intended_shift": "区分比例变化、融资代价与资金用途",
    "author_position": "先看经营与资本配置，再形成判断；个人偏好不写成普遍定律",
    "chapters": [
      {"id":"c-question","question":"直觉遗漏了什么？","changes":"从消息好坏转向具体代价","bridge":"接着需要知道钱用在哪里","units":["u-opening","u-cost"]},
      {"id":"c-evidence","question":"公告证明了什么？","changes":"用途计划不等于投资回报已实现","bridge":"回到下一次读公告的检查问题","units":["u-evidence","u-ending"]}
    ]
  }
}
```

章节必须按顺序、无遗漏、无重复覆盖 units。程序检查映射与必填项，不证明论证正确。每段 argument 继续维护判断、依据、边界；不会因 narrative 存在而免除来源核验。

## 审稿实例

- 不足：“这是护城河，所以公司好。”改进：指出竞争者具体做不到什么、为什么做不到，以及什么变化会削弱它。
- 不足：“公告写了研发，所以融资值得。”改进：公告只能证明计划用途；实际投入、回报与融资成本仍需后续资料。
- 不足：连续三个故事重复同一结论。改进：保留最贴近观众的一个，剩下的时间用于反例或边界。

保留作者原稿在 source。需要改动作者立场时明确指出原因；不要虚构亲身交易经历或模仿参考博主的口头禅。
