# 分镜素材编导

本 skill 由 agent 执行，负责素材准备与交接，不是已接入 youtube-studio run 的无人值守搜索服务。先读 script.json、brief.json 和已存在的 build/timeline.json；保留作者录音，不因找音乐而触发 TTS。图片/视频/BGM/SFX 的准备与最终渲染是不同完成状态。

将短样片配乐扩展到完整篇时，依据实测章节与论证转折安排编配、密度和音量变化，不把短音轨无说明地拉长或让其超出源文件。需要循环时保留原件，生成可核对时长的交叉淡化衍生音轨，记录源哈希、许可和处理方式；检查循环接缝、跨章衔接及旁白停顿处的听感。继续保持作者认可的情绪基调，反例和风险段不因此自动改成紧张音乐。

参照本仓库 [小A调研](../../docs/research/xiaoa-investment-series-analysis.md) 的实拍承接、实物拼贴、单一关系变化。不要直接复用参考视频素材、人物或声音，也不声称已经复刻其未听审的音乐与音效。关键是找到能承载动作的对象，例如“同一瓶水换环境”，而不是对每句话搜索“投资、金融、办公室”。

## 从表达任务形成素材需求

封面照片按 [封面照片与频道标识](../youtube-visuals/SKILL.md#封面照片与频道标识) 从最终脚本提炼生成需求，不用泛财经图库照片替代用户要求的内容生成。实际生成时使用环境可用的 imagegen 能力并遵循其工作流；记录采用的脚本版本、对应主张、完整提示词、实际文件与哈希，将其标记为生成的摄影式情境图，不登记成实拍证据。标题与logo留给独立排版，避免在照片里生成错字或伪标识。

生成前记录主体的主题辨识与可能误读，以及画面中真正可见的选择、对比或变化。若信息依赖价签、复盘文字或行情数字，先确定其内容和证据/假设性质，再预留独立排版位置；不能交付空白道具后声称已表达该关系。需要作者人像时先复用已确认素材，不用陌生人或生成面孔冒充作者；概念行情与模拟凭证不得包装成真实截图或当前报价。

采用“复盘材料＋手持笔”方案时，从真实记录选取与本期判断直接相关的最小节选，保留原文及来源位置，避免带出账户细节。手、纸和圈注可生成情境重构，但不能称为原稿实拍；如纸面文字随照片生成，必须逐字核对日期、引文、标点与否定词，检查手和圈线没有遮字，出错先修图再交付。主标题与原版logo继续独立排版，人物动作和选用记录按每期脚本确定，不固定套用同一桌面模板。

“面朝北北”logo复用公共原件 `resources/branding/mianchao-beibei.svg` 及同目录来源记录。制作时冻结副本到本期 `media/branding/`，核对哈希并登记台账；不重新生成、描摹或拉伸原标识。原件确实缺失时先查公共素材和既有来源，仍无法恢复才报告具体缺项，不能把占位文字当作正式logo。

先承接 [youtube-visuals](../youtube-visuals/SKILL.md) 的对象与动作规划，按“主体＋动作＋环境＋解释任务”检索，例如“咖啡店店员把咖啡递给顾客”，不按每句口播搜一张泛财经配图。优先考虑能被裁切、连续跟踪或独立移动的对象。

每个需要媒体的镜头写入 media-plan.json，格式见 [素材契约](references/media-contract.md)。说明画面要证明、演示或建立什么情境，主体/动作/环境、中文和英文检索词、所需时长、与口播 cue 的关系，以及为何现有素材不足。没有实测时间线时不编造秒数。

- 生活情境：找主体明确、动作可辨、可裁切的真实短视频或照片；优先维持同一对象或空间。
- 机制：找可独立操作的实物图片或剪贴对象，与图解配合；顾客分流、商品复制、订单增加比泛化条形图更直观。
- 事实证据：找与公司、日期、事件匹配的原始公告/报告；通用素材不能承担证据角色。
- SFX：绑定开门、物体落位、复制、敲击或结论落定等具体事件。可以选择 none，不给每个字和每次切镜头都加 whoosh。
- 本项目音乐优先选择允许商业网络视频且不要求署名的许可。检查具体曲目来源和官方许可；Mixkit可作为来源，YouTube音频库须筛选无需署名，不能把所有免费音乐都当成免署名。后台仍记录作者、许可与来源，不必将它们叠放在画面。未试听保留pending，不声称不会遇到Content ID。
- BGM：按叙述气氛、密度、是否有人声、可循环性选择。BPM 是可选节拍参数，不是背景音乐的同义词；不要把估计值写成测量值。音乐节奏服从作者语音，不为踩点改坏论证。无配乐也能成立时可以不选 BGM；不得把样片的“两处 click、无 BGM”固化成所有主题的规定。
- 用户反馈音乐单调时，先写音乐叙事表：每次转折的口播 cue、当前情绪、下一段需要的音色/律动/密度、进入/退出与留白理由，再选曲。连续承接不等于一首均匀铺满。可在同一曲目的不同段落间发展，也可换曲或撤掉节奏；不规定曲目数量，不按固定秒数轮换。仅调音量或侧链不算音乐发展。候选要比较实际采用片段，排除抢话、过度煽情或与论点不符的素材，未试听明确 pending。
- 选定音乐和音效时检查实际裁切点、尾音与底噪；“可循环”标签不代表接缝已试听。换镜不默认重启配乐或添加转场音效，实拍原声须明确是否保留。混音和最终编码后的切换检查交给 [接缝与转场声音检查](../youtube-voice/references/voice.md#接缝与转场声音检查)。

## 搜索、筛选与冻结

作者当前偏好：整体轻松、放松，带温暖而循序渐进的成长感。先守住全片基调，再在相近音色与和声语言里变化乐器层次、旋律段落和轻柔律动；可优先比较同一作品的稀疏与丰满编配。风险提醒不自动切成悬疑、暗色爵士、紧迫节奏或戏剧性断音；成长也不等于热血冲刺。具体选段仍须听审音色、和声张力及鼓点，曲名带happy或音量小不等于已符合偏好。后续用户指定其他基调时，以本期要求为准。

1. 先查剧集现有 media 和有来源记录的可复用素材。相关性优先于凑素材数量；已有素材只在用途确实一致时复用。
2. 环境提供 media-use 时先读取其 SKILL.md、resolve 参考并执行 doctor；用 candidates 查看候选，再用 resolve 检索 image / bgm / sfx。不根据 skill 的描述假定外部 CLI 已安装或账号已登录。具体命令与当前边界见素材契约。
3. 实拍视频用已可用的素材站搜索/API或网页工具寻找，打开素材详情页及许可页后，通过站点提供的下载入口获取。先确认接口真实支持视频检索；生成头像视频不能替代实拍素材搜索。不因一个 provider 缺失就停掉其他可完成的素材类别。
4. 每项先比较少量相关候选，选择最适合解释任务的一项；不把第一条搜索结果自动设为最终素材。记录选择理由和排除原因。找不到合适素材时保留缺口或提出具体图解替代，不能悄悄换成 AI 插画。
5. 下载到 media 下的 photos、footage、sfx、bgm 等子目录。使用实际文件做检查，登记路径、SHA-256、来源页、许可、作者、必要署名和使用限制。不绕过登录、付费或下载限制；访问失败后换可访问来源，不能改写为已完成。
6. 看图片主体与裁切；视频检查选用区间的前/中/后帧及运动是否合适；音频检查实际时长、是否有人声和可用段落。未试听/未播放的项目保留 pending，不用波形或标题代替听感判断。

用户已授权制作时连续完成正常检索与下载，不逐张征求确认；新付费购买、账号授权等依实际授权处理。请求结果不确定时先查状态，避免重复计费。凭证不写入素材台账。

## 交接

投资事实与研究材料先读 [trade 研究交接](../youtube-write/references/trade-context.md)。trade 的论点说明画面要支持什么，证据画面仍追到原始资料及页码；普通图库素材只建立情境，不能替代公司事实。截图和图表保留期间、单位、口径与关键限制，不因裁切或美化移除反证。个人笔记默认供理解，公开画面优先使用必要节选，避免暴露无关账户信息。

输出 media-plan.json、media/manifest.json 和简短的 media-review.md，列出已保存素材、镜头对应关系、未完成项及渲染接入状态。不要只有推荐网址。

当前程序可将图片回填 collage / illustration，将实拍回填 footage，将 SFX/BGM 回填单元 audio_tracks；视频裁切、静音、音轨混合及人声侧链压低已接入。字段见 [作者契约](../youtube-write/references/authoring.md)；能力验证范围见 [连续场景实施记录](../../docs/decisions/continuous-scene-implementation-2026-10-24.md)，不把某次样片验证当作新素材已播放或已听审。回填后执行 validate 和 doctor，并把编排交给 [youtube-visuals](../youtube-visuals/SKILL.md)。未经实现验证的视频与音频轨道写入素材计划，不伪造 shot.kind 或混音字段。正式成片交给 [youtube-produce](../youtube-produce/SKILL.md)。

普通素材搜集不自动重写口播、重配音、重渲染或发布视频；用户要求完整制作时按原授权继续。

## 跨期复用与恢复

使用 [共享素材库](references/library.md) 的 search/check/freeze。先按主体、动作、环境和用途查找，复用前重新判断当前论证是否适合。冻结会复制素材到本期 media/library，保留源哈希与恢复信息；不直接依赖其他剧集的可变文件。

作品库和工作台中的长期媒体按各库 .gitattributes 使用 Git LFS；运行缓存不入 Git。提交大媒体前先核实本机 LFS 可用。索引、来源、许可、裁切范围与恢复位置继续入版本管理；干净检出后先检查缺失文件，不能把 metadata 存在当作素材齐全。

讲具体应用时，优先从开发者发布的商店页或产品官网取得标识和产品展示图，核对发行方、应用名和图中产品。活动版图标带剧名时，可保留完整品牌图形并记录裁切。把识别产品、展示使用场景、证明财务判断分配给相应的图标、界面或公告原文，分别保存出处和指纹。给数据卡配图时标清图像是产品展示，指标另外注明统计来源。

用户指出成片缺少配乐时，先查最终混音实际引用，再按章节选用有许可的无唱词编配，保存来源、变奏、淡入退场和避让人声的设置。导出后在开场、连续数字、章间和片尾核对音乐贡献，提供直接来自 MP4 的有声片段。
