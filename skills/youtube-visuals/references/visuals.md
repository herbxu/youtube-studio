# 观点视频的对象与动作设计

当前优先方向：观点口播主导，真实素材建立情境，持续存在的对象解释机制，少量短句收住判断。摄影拼贴是可选版式。统一字体、标注与配色，不要求每个镜头长成同一页。

## 先拆变化，再选素材

为关键解释段明确以下内容，写入 brief 的制作规划或已有分镜说明；最终把可执行内容回填 script.json，不新增未经实现的 shot 字段。

| 项目 | 应回答的问题 |
|---|---|
| 对象 | 观众跟踪的是谁、什么物件或哪一组数量？ |
| 起始状态 | 动作前谁拥有它、位于哪里、关系怎样？ |
| 动作与结果 | 是进入、移动、分流、复制、分配还是强调？结果如何可见？ |
| 口播锚点 | 哪个真实说出的词触发动作？素材需要持续多久？ |
| 表达边界 | 是事实证据、假设示意还是生活情境？哪些条件影响结果？ |

先观察变化，再给出判断。讨论同一对象时不因 unit 边界重新入场、换背景或重置状态；真正换话题、换证据或换尺度时再转场。连续对象不等于必须一镜到底，也不要求固定几秒换画面。

例如竞争机制可以让同一批顾客从原店分流到其他店，再观察原店订单减少。图符数量仅作示意，并注明需求、单价、成本条件；不能把“订单减少”直接当成所有情境下“利润减少”的证明。不同主题重新选择对象和机制，不强制咖啡店、12 位顾客或同一动作序列。

## 文字、构图与运镜

### 素材相关性与减法审阅

针对“无关、杂乱、不清楚”的反馈，逐镜头记录口播正在回答的问题、画面主焦点，以及每个主要元素的作用。对照片、人物、图标、数字、标题分别做删除检查：去掉后若不损失对象识别、证据可信度或关系理解，就优先删除。装饰性摄影不因已获许可、制作过或看起来真实而自动保留。

- 财经题材不自动使用计算器、交易屏、咖啡店或陌生人物。生活情境只有在旁白确实借它解释具体生意或动作时才使用；不能让观众额外猜测它与投资对象的关系。
- 同一时刻保留一个明确主焦点和必要的辅助关系。数字已清楚表达数量时，不再默认叠加等量金币；标题、解释正文和字幕不重复争夺注意力。来源与关键假设仍需清晰可读，可放在稳定的次要层级。
- 解释价格与收入时，保持同一对象和单位，只改变正在讨论的变量；例如买价下降时保留收入，讨论经营恶化时再改变收入。算式到解释比例时才出现，避免照片、多个数字、图标与结论同时涌入。
- 作者经历优先呈现必要的真实记录节选与对应强调，不以无关桌面照片代替个人证据。减少装饰不等于把整段讲稿铺满画面；关系与变化仍由对象动画承担。
- 在实际导出帧及缩小播放尺寸下检查：能否立即指出正在解释的对象、发生了什么变化、与哪句口播相连。若必须依赖长篇解释才能理解配图，重新选材或删去。分别记录语义清晰度、文字可读性和连续观看结果，布局无碰撞不等于清晰。

- 实拍时通常保留一个必要问题或关键词；机制变化时保留对象标签和条件；结论时才突出短句。字幕跟随声音，不另加一段几乎相同的正文。
- 不默认固定刊头、页码或每段一个大标题。保持来源、必要条件和字幕可读；具体署名展示遵循素材要求，不因减少文字而丢失来源。
- 运动由作用决定：对象真的移动或被复制，关键字可强调，条件与来源保持稳定。整组出现、分组进入、替换或停留都可用；不默认所有文字上浮、变红、画下划线。
- 当前 headline_parts 的效果是组内上移渐入与可选强调线，适合有限的判断强调，不是可任选多种效果的通用文字引擎。其他文字运动需扩展生成器后验证。
- 动画结束后留出阅读时间。标题分组当前契约要求锚点距镜头结尾至少 1.25 秒；这是该模板的校验约束，不是所有文本都要按固定时长播放。
- 复制时保留来源对象，让副本到达明确目标。多个标签可保持组内间距，经独立路径移动；检查途中是否穿过其他文字，不只看起点和终点。
- 相同照片复用需承担新的解释动作；只有主体变化或观察尺度需要时才推拉、平移、裁切。单纯重复慢放大不能替代机制演示。

可延用浅纸色 #f4f0e4、深墨 #202724、砖红 #ae3d2f。真实摄影保留自然色彩，图解用颜色区分对象与变化。全画幅实拍与纸色图解可以交替；检查裁切是否损失人物、手部动作或关键物件。需要调色或媒体特效时按可用 media-use 工作流处理，不默认加 LUT、颗粒或滤镜。

## 当前配置与兼容模板

连续街区样片使用 style.id=continuous-explainer/v1。init 默认读取 opinion-explainer/v1；制作连续场景时显式设置该剧集配置，不能只改 brief 就宣称运行时风格已切换。历史剧集不批量改写。

footage 接收本地视频，按 source_in 和实测镜头时长冻结为静音 H.264/30fps，focus 控制裁切。视频时长不足会报错，不自动循环或用静帧补齐。

continuity / shop-competition/v1 是现有专用实现：跨 unit 的同一 DOM 场景，按真实 cue 执行完整的进入—分流—复制过程。动作清单和顺序见 [作者契约](../../youtube-write/references/authoring.md)。其他关系优先选择已实现的 object_scene；未覆盖的动作仍需扩展。

collage 保留 hero 和 duo；图片与第二素材需要独立来源。mechanism 的 competition/convergence 保留兼容，但无定义的利润色块或“领先距离”条形图不应作为连续对象解释的默认替代。两类杂志版式搭配 editorial-magazine/v1。quantity 只支持固定持有量与变化总量。

原始财报、公告和数据用来支持事实。evidence 已支持真实截图的局部高亮；截图获取和内容核验仍由 agent 完成，不能手写截图内容冒充原始材料。

## 时间线和声音

实际录音是主时钟。cue、label_cues、headline_parts[].cue、events[].cue 各按支持的模板定位；精确动作不能落在未匹配的识别字符上。标题组内部错开是动画设计，不等于逐字 ASR 同步。

先使画面在没有配乐时成立，再决定是否需要 SFX/BGM。声音只支持动作或叙事气氛；不为逐字动画机械加 whoosh，不为 BPM 改坏句群节奏。素材与声音交给 [youtube-media](../../youtube-media/SKILL.md) 和 [youtube-voice](../../youtube-voice/SKILL.md)。

HyperFrames 使用单条 paused GSAP 时间线；框架负责 clip 与媒体播放，内部对象负责运动。所有渲染资产冻结到本地，不引入随机、网络或实时钟。

## 检查实际导出

### 语义分组与整幅构图

当反馈是“布局不好、文字散、主次不明”时，先检查关系是否被拆散，再调整单个元素的居中。把一句判断或一个比较关系当作整体：逻辑相连的短语采用共同基线，按实际字形占宽计算组内间距，再将整组放到画面主视觉区。不能给每个短语各分一块宽大的居中区域，造成框都对齐、文字却相隔很远；连接词或关系符号不应变成孤立角落或淡到难读的残片。可删去不影响含义的口语连接词，但不能省略必要条件或改变结论。

旧对象与新结论分阶段安排。旧标签完成解释作用后退场或明确降为辅助；只有新结论需要持续参照它时才保留。不能一边保留抢眼的大卡片，一边把真正的主张挤在下方。标题、关系式、条件和字幕的层级由当前讲述任务决定，不机械固定为“大框在上、短语在下”。

入场动作服务于语义组合：先出现条件、后补动作时，安排整体位置过渡，让最终短句连成一组；不要让几个短语从相反方向长距离飞入后仍散在画面各处。分别看首次出现、组合中、落定后，以及旧对象退场后的重心。对关系式检查符号与两侧文字的基线、间距和完整性；同类文字卡片一起复查。验收同时看整帧及缩至约640像素宽的画面，记录主焦点、组内距离和旧内容是否抢占视线。字形居中、无碰撞与语义构图是三项不同检查，前两项通过不能替代后一项。

文字卡片的框宽按文字实际占宽和适量内边距决定，不默认做成横跨画面的大矩形。用户反馈“框太长”时，保持已合适的字号与视觉中心，优先收窄左右空白；不要把文字一起缩小。短标签可从每侧约0.8–1.2个字宽的留白试起，再根据边框、装饰及运动空间调整，这只是起点而非统一尺寸。分别检查居中、框的紧凑程度和整幅画面的比例，居中通过不代表框宽合适。

文字与矩形不对齐时，区分边框几何中心、字体行框中心和可见字形中心。检查实际加载字体与字重、行高、内边距及末尾字距，不能只看flex居中属性。框和文字共用一个动画父对象；光学校正放在内部文字层，避免旋转/缩放时错位。检查所有同类卡片、印章和字幕，在进入中、稳定后及缩放/旋转后量取可见字形与框的中心差，并查看真实导出裁图。更换字体或字重后重新测量，不把某一字号的固定像素偏移推广到所有文字。

用户反馈“像PPT、文字无用、一下子出来、没有重点”时，先给每个可见元素写作用与首次需要它的口播 cue。重复标题、栏目眉题、已被口播/字幕解释且无定位作用的正文删除；来源记录留在脚本与台账，公开画面保留理解所需的出处和假设条件，不能借减字删去限制。主画面只承担当前关系，不预先把整页对象和结论摆满。

动画应改变观众需要理解的对象或关系，例如原价格连续变低而收入保持原位、成本条缩短、错误判断被纠正。先建立对象，再发生变化，再留出读结果的时间；已讲完对象降为次要或退场。标题依次飞入、整页慢淡入、划一条线后长时间不变，都不能独立解决PPT感。同一对象跨句群保持位置与身份，真实变化才切换焦点；不为增加动画量把快切问题重新带回。

编排前记录每个重点的“出现前 / 动作中 / 落定后 / 下一变化”状态；新文本的落定后可读时间按实际语音计算。最终检查应包含片段开头、主动作和落定画面，不能只看中点截图。数值、数量与比例在变化中和变化后都要核对；只有解释性对象运动才算本项修复证据。

用户反馈画面太快时，截取切口前后与关键元素出现后的连续帧，结合实际时间线计算“动画完成到下一变化”的可读停留，而非只报整镜头平均时长。一个16秒镜头可能把关键算式留到最后1秒才显示；一个强调线也可能刚画完就换页。优先减少新的阅读任务，让同一关系持续存在，必要时把已讲清的结果延续到下一句；不要仅把转场动画变慢。画面、停顿与配乐一起安排：先建立对象，讲清变化，留出理解空间，再转向新问题。截图只证明画面与时序，不替代连续观看或声音听审。

1. 查看实拍选用区间的前、中、后帧，确认人物/物件、动作和裁切；再核对实际 MP4，防止预览正确而导出冻结或缺失。
2. 检查对象变化前、运动中、落定后及转场。对象身份、数量、方向和图解假设保持一致；复制过程不碰撞文字、不遮挡条件或字幕。
3. 运行 `node tests/check_composition.cjs <剧集目录>` 检查已覆盖模板的倒序 seek、复制避碰、媒体时序和字幕框；新模板需补充有意义的验证，不能沿用旧测试结论。
4. 抽帧检查与连续播放、主观听审分开写入 review.json，并绑定当前 MP4 哈希。响度与文字匹配不证明表达自然；未执行的检查保留 pending。
