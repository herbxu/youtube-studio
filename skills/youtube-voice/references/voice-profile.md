# 作者音色、读音与最终听审

本期 source/voice-profile.json 记录音色来源、用户授权说明、参考文件哈希、服务与 voice_id 状态、需要试听的问题。实际执行配置仍在 config.json.voice，不维护第二套运行参数。音色参考不能填入 unit.audio；那里只接受本单元真实旁白。

制作克隆声音前验证服务支持、账户与语言。先生成一个包含提问、数字、转折、收束的短样本；只在实际听审后登记 voice_verified。服务尚未选定、未配置或样本未审听时标记 pending/blocked。不要猜 voice_id，不把 OpenAI 的预置音色说成上传 MP3 后的同音色。

新稿维护本期读音表，必要时参考 config/pronunciations.json。读音展开写 spoken_text，保留语义；最终字幕当前也使用 spoken_text，需检查长数字读法是否过于拥挤。不盲目全局替换多义词。

审听按实际片段记录：

| 类型 | 检查 |
|---|---|
| 提问 | 是否能听出在邀请思考，是否过度上扬 |
| 解释 | 句群是否连贯，主语和指代是否清楚 |
| 转折 | “但是/如果/只有”是否承接前文，否定有没有漏读 |
| 数字 | 数量、单位、比例是否清楚，是否留出理解空间 |
| 收束 | 是否回到本期问题，结论强度与条件是否一致 |
| 剪辑/混音 | 接缝、呼吸、重复停顿、SFX 落点、BGM 遮蔽 |

完整听审与抽查分开记录，注明时间区间；音量合格不等于表达自然。没有播放能力时准确保留 pending。音色样本很长时先选择干净、单人、无明显配乐的区间，保留原件和剪辑依据。

## 音色相似度返工

声音身份、表达自然度、文字准确性分别验收。“B 更合适”是当时候选间的偏好，不能推导为此后任意稿件、表达指令和后期处理均像本人。用户否定当前成片时，将本版 audio 记为 failed，保留此前选择记录，并在 voice-profile 中写明当前拒绝结论；不覆盖成此前从未授权。

1. 查找已有本人原录音、实际用于注册的截取段、注册回执、候选试听和本期原始合成文件，核对路径与哈希。继承的档案引用须能实际解析到原剧集文件；不能仅复制 voice_id 和“已验证”标签，也不要让用户重复提供已经存在的录音。
2. 做短段对照：本人原声、未经变速/混音的合成声、最终处理声。比较版本时使用同一文本，优先选已有录音中的一小段作合成测试；仅作适当响度匹配，保留原始文件。分别记录声线/共鸣、口音和习惯发音、重音与句尾、气息和句群节奏。仅凭 ASR、响度或频谱不能宣布像本人。
3. 原始合成就不像时检查参考截取与注册音色；后期才变差时检查变速、局部强调、压缩与混音。表达指令有变化时先比较基础设置与新增指令，每次只改变一个主要变量。尚未听审时只能把它们记为待核查变量，不能宣称已找到失真原因。
4. 约定时长允许小幅浮动时，优先保住作者说话节奏，必要时删改冗余稿件；不默认统一提速来卡时长。任何变速或表达调整后，重新检查最终声音，不能沿用处理前的试听结论。
5. 先验证一段包含本期解释与数字的短样，不反复付费重做整片来碰运气。用户已明确否定声音身份时，新候选的相似度需要获得实际试听反馈；已有授权可继续用于局部排查，不等于质量通过。无主观试听能力或尚无反馈时保留 pending，视觉等独立工作可继续。

用户在反馈后明确要求生成新版样片时，按授权完成可播放样片供试听，不再把待主观评价变成重复确认。若恢复历史偏好的基础设置，核对当时候选的实际请求（包括空 instruction、是否启用 unit.delivery、语速和后期增益），不能只沿用同一个 voice_id。保留旧版和前后参数；本版声音相似度仍记 pending，不写成已获认可，也不为绕过配置检查虚构新的听审记录。

收到笼统的声音反馈时，沿当前成片回溯到剪辑引用的录音与最初合成。导入音频的当前速度为 1.0，并不能证明上游从未变速。记录源文件实际解码时长、处理速度、保留的语句区间和接点。优先从旧成片和原合成截取同一句问话或判断，匹配响度并清楚标明还有哪些后期差别。测试恢复原速时直接取原始声音，按词边界重新剪接、对齐字幕和动作。把可证实的处理变化和待作者试听的音色、重音及自然度分开记录。

当作者把问题指向“发空、发闷或不像本人”，从已有原录音里找一句稿件和词边界都能核对的原话。用同一注册音色和模型分别生成当前表达设置、关掉表达指令的版本，和本人原录音按固定顺序等响串联；为每段留可辨的间隔，记录参考区间、实际响度及候选设置。另用本期同句的原合成与导出音轨检查后期是否明显改变频谱。只能把频谱变化作为排查线索；若两版合成均不像，应回到参考录音与复刻音色，不继续靠提亮或变速尝试解决身份差异。

作者选出“更像”的段落后，把试听序号对应到实际音频和请求设置，再重配已约定的试剪范围。在新录音上重新对齐字幕与关键动作，抽查问句和连续数字。记录作者对该候选的偏好，并单独保留新成片的听审状态。

观众反馈段落衔接生硬时，约一分钟到两分钟的连续解释可用已选音色一次录完整段。若识别需要短单元，先用全段独立转写定位语义边界，再在附近低能量处无损切分；逐样本核对重组结果等于原录音。不要因画面切换插固定停顿。单独检查孤立数字的误识与上下文转写，完整自然度听审另记。

全片合成前建立数字和品牌对照：显示“约 4.3 亿、3.55 亿、手机 QQ”，合成稿分别用“约四点三亿、三点五五亿、手机 QQ”，保留两个 Q 的英文字母音。检查数字和单位是否同句、源精度和约数是否一致，另审年份、时长、百分比。按 AGENTS.md 固定台词录制片头问候和频道落款，道别读完后留约两秒。

开场被指出太赶时，分别测问候、主题、提问和判断的词速与句间低音量间隔。优先压短口播再用已选音色连读，可适度保音高放慢局部并在问句后留呼吸。按最终音轨重做字幕对齐，核对问题后的留白与进入下一段的接缝。

声画联检直接解码交付 MP4。测相邻两句的实际有声间隔，并把换镜时间、首字起音和字幕入场并排核对。遇到停顿突兀，先查前句尾静音和后句头静音，剪前确认词首仍完整。校验响度、峰值、各段音量差并抽取无提示转写；在验收中区分可测的错位和需人耳判断的音色、重音与发音。

调整开场前先测正文相邻两段和全片中位字速，区分有效发声与段首尾留白；允许封面、导航和首个证据镜头跟随新录音提前。用同一正文做上下文，比较改前改后“问候→问题→判断→第一笔证据”的连续试听，不能只听孤立片头。

作者指出片头与正文“语调不同”时，用同一文案、同一注册音色对比两条连续样本，含问候、第一笔数据和一段原正文。核查分开合成或连续合成、表达指令和后期变速；分别比较问候、提问、判断的音高轮廓、重音和句尾收束。基频只用于定位可复听处，优先听整句的交谈感。试录后核对用词和数字，记录是否实际替换成片。

连续试录改善了语气、但作者反馈音色偏离时，保留连续文本和原速，只撤回新增表达指令。把本人原声与已选历史候选的同一句、被否定版与修订版的同一句配成两组等响度试听，标示顺序与断点。逐项记下被否定版本与待听版本，不能将新候选直接提升为频道基准。

统计口径“去重”读 qù chóng，重与“虫”同声母、韵母、声调。引擎多音字误判时，用批准的原音色重录所在短句，必要时仅在合成输入用同音字辅助；在静音边界接回，字幕和图表保留原字。把带背景音乐的实际成片例句一并导出复核，ASR 写出“去重”不能区分两个读音。

作者点选某个音色片段时，登记对照文件、该片段起止、对应的原始录音及适用范围。正式换入时对照原录音与最终 MP4 的同一句，连听下一句原正文；新合成的句子单独标记。
