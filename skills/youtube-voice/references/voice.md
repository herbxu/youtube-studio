# 配音与时间

正式 provider 在 config.json 的 voice 中配置；同一期保持模型和音色一致，全局指令定义一致的讲述方式，段落表达按服务实际能力传递。支持 OpenAI、Aliyun、command、逐段本地 audio；macOS say 只用于 preview。

配音前核对当前适配器的真实参数路径：目前 OpenAI 仅在配置了 instructions 时附加 unit.delivery；command 将 delivery 交给外部命令，仍需检查其消费情况；Aliyun 默认读取 settings.instruction，启用 settings.use_unit_delivery=true 后才合并 unit.delivery，并在语音 receipt 中记录实际 instruction。此开关仅接受已核对支持自然语言指令的 Qwen-Audio-3.x 与 CosyVoice-v3.5 系列；后者合并后仍受100个计数字符限制。依据[官方指令说明](https://help.aliyun.com/zh/model-studio/non-realtime-tts-user-guide)，本项目已验证Qwen-Audio-3.0复刻音色的参数传递与实际返回，不等于自然度自动通过。需要逐段表达时先落实支持的传递方式并验证代表性短段，再批量。不把表演备注直接塞进 spoken_text 让模型读出。

本地录音：将文件复制到 media/，在对应 unit.audio 填相对路径。一个文件应只包含该单元实际口播；不得把一整期录音指向每个 unit。参考录音仅用于分析，不能冒充新脚本的配音。

音频先转为 48 kHz 单声道 PCM16，再按单元顺序拼接。程序不额外添加固定静音；段落停顿由实际音频决定。母带先确定双声道布局，再执行两遍 loudnorm 测量与处理，并保持原始 PCM 时长，默认目标 -18 LUFS、峰值上限 -1.5 dBTP。渲染器因此无需再次把单声道复制成双声道，避免成片响度多出约 3 LU。实际 MP4 还会重新测量响度和真峰值；听感需另外校验。

用户认可音色但希望调整语速时，可在 config.json 设置 `audio.voice_speed`（默认1，范围0.75–1.25）。例如0.9表示原速度的90%。归一化阶段使用 FFmpeg atempo 保持音高的时间伸缩，复用原始TTS缓存，不向服务重新提交配音请求。随后依据变速后的真实音频重新对齐字幕和动画，原始录音保持不变。有导入的 `unit.words` 时拒绝直接变速，必须先移除旧时间戳引用并重新对齐。不要把均匀放慢称作重新设计了语气和句群节奏。

少量关键判断可配置 `unit.voice_emphasis`：每项包含唯一 cue、gain_db（0–3）、speed（0.85–1）、pause_before（0–0.25秒）。需要 whisper-forced，先将短句定位到实测词边界，再做局部增益、保持音高的变速及短暂停顿，并重新对齐最终输出。不修改原始TTS、不重发合成请求、不声称模型重新演绎了情绪。选完整转折句或判断句，避免密集切碎词语；主观自然度另行听审。来源/输出哈希、实测编辑区间和参数写入 build/voice-performance.json。

alignment 默认 faster-whisper 中文词时间戳。对每个 unit 计算原稿与识别文本的匹配，并定位分镜 cue；数字/术语的 critical_terms 要完整匹配。允许少量普通识别差异时，字幕文本仍来自原稿，同时在 timeline 的 unmatched 中显式记录；精确动画锚点不能落在未匹配字符上。中文词内部可能细分字符时间，这不等于音素级 forced alignment。

成功对齐后 `build/voice-review.json` 保存每单元的 differences，包含替换、缺失和额外识别内容；audio_range 相对本单元音频，需加该单元 start 才是母带时间。没有差异只代表文本匹配，不代表已完成主观听审。导入已校正时间戳时明确记录 method，不把它说成一次新的独立识别。

若识别错误，优先检查读音展开、录音质量，再选择更准确的识别服务。可导入 unit.words，内容为真实时间戳 JSON，起止时间相对本段音频。不允许按整段字数估算冒充真实对齐，也不允许修改原稿迎合错误识别。

句群之间可以短暂停顿，列举内部保持连贯；不固定每句 0.3 秒、每个观点 0.8 秒等机械节奏。小A开头样本约每分钟 250–300 汉字、思维咖啡全片转写粗估约 281 字/分钟，样本范围与算法不同，不作为统一速度标准；详见 docs/research 的测量边界。

用户认可音色但反馈太快、缺少聊天感时，保留音色与已认可的基础设置，优先删去重复解释、把书面结论改为有来有回的问答，再按本段听感调整语速。没有技术变速不代表讲述不快；记录各段含停顿的字速，用来找密集段，不把统一字速当自然度标准。只放慢整条音频不能算完成聊天感改造。

需要明确思考空间时可用 `unit.voice_pauses=[{"after":"唯一的完整句群末尾","seconds":0.8}]`。seconds 是期望的词间停顿总长（0.2–1.5秒），已有间隙足够则不追加。程序用真实强制对齐与低能量区选择接缝，保留尾音，找不到安静区就失败；不能用于片尾补时长。记录实际追加量、接缝电平及输入输出哈希，随后重新对齐。该操作仅是局部节奏编辑，不声称生成了真实呼吸或重新演绎情绪。

用户要求停顿配合BGM时，音乐应连续承接句群间空隙，人声开始时压低、停顿时平滑恢复；不要每句或每张画面重启音乐，也不要在短暂停顿里突然顶高。先核对曲目来源、乐句、实际电平，再听最终混音。无配乐人声和混音分别保留，检查停顿是否仍像断线、侧链是否抽吸；未听审记pending。音乐不能掩盖语速过快或信息过密。

连续配乐不是全片一首背景声。把音乐转换落在实际叙事转折，例如从个人回忆进入算例，或从收益解释转向失效条件；乐器、律动、密度与有意留白应有理由。先保留已认可的人声与停顿，再混入新音乐。记录曲目区间、入点、淡变重叠、增益与无配乐区间；检查重叠峰值、退出尾音和停顿中的恢复速度。素材片段听审、最终转折听审和全片听审分别记录，不能用“已换三首”代替“转换自然”。

不能只核对轨道配置或第一段音乐。多段配乐必须逐段验证实际混音中的进入、退出与预定留白，并检查最终MP4确实包含该混音。延后入点、非零 source_in、侧链和补齐组合要有信号回归检查，防止轨道出现在片头或被裁掉；信号检查只能证明存在和时序，不证明音乐合适。不得把预期秒数写成已听到的结果。

完整字段与 command 协议见 [运行契约](../../youtube-produce/references/runtime.md)。


## 剪辑与混音交接

内容修改应落到实际音频。保留原始录音，剪辑记录写清原片区间、输出区间、删除文本、淡入淡出和新增停顿；字幕须与实际说出的内容一致。裁掉结尾并保持前段不动时可保留前段已核对时间戳；中段删除会改变后续时间，需据实重算或重新对齐。记录实际方法，不把沿用词时间称作新识别。

声轨顺序为：原始单元录音 → voice 阶段归一化和人声母带 → align 实测锚点 → assets 阶段冻结附加音轨并混音。单元 audio_tracks 的字段统一见 [作者契约](../../youtube-write/references/authoring.md)，不另造平行混音配置。

有附加音轨时，build/audio.mixed.wav 是成片所用音频，build/voice.master.wav 单独保留；没有附加音轨时使用人声母带。混音使用真实 cue、源区间、gain_db 和 fade，duck=true 让人声触发附加音轨压低。音轨不能超出源文件或成片，不自动循环，不支持额外 offset。声音落点若需要精确晚于 cue，先扩展能力，不能在素材计划中写了偏移就声称已执行。

机器验收包括时长、响度和真峰值；主观听审另外核对剪辑接缝、停顿、语气、字音、音效落点和 BGM 是否遮蔽口播。单独试听素材不等于听过最终混音。不能用信号测试证明选曲合适，也不能从文件名猜 BPM。

## 接缝与转场声音检查

当全片要求轻松成长感时，配乐变化应保持温暖基调，以稀疏到丰富的编配、轻柔律动和适度回落承接口播。谈风险也保持平和解释，不用悬疑低音、紧迫鼓点或突然抽掉全部背景来制造压力。认可的人声与停顿优先保留；先替换不合适的选段，单纯压低紧张音乐不能修复情绪方向。仍需分别记录选段与最终混音听审结果。

目标是切换时没有可闻的爆音、短促点击、重复音、断字和突兀的底噪跳变。用户说“切换有杂音”并不能确定根因；不要直接归因于 TTS、配乐或视频拼接。

1. **定位层级。** 根据实际时间线列出单元接缝、局部重音/变速编辑的出入口、BGM/SFX 起止与章节切点。对可疑点分别听原单元、人声母带、混音母带和最终 MP4 的前后约 1–2 秒，必要时扩大到完整句子。母带干净而 MP4 有问题时，查编码、封装和播放器；不要先重做配音。波形突变、直流偏移、削波与瞬时能量只用于筛选疑点，不能代替听审。
2. **人声接缝。** 优先在自然停顿和低能量处衔接，保留尾音、呼吸和首辅音。存在硬切点击时，可从约 5–15 毫秒的边缘微淡化试起，按实际音频调整；不能对每个词机械加淡入淡出。交叉淡化只放在允许重叠的停顿或底噪区，避免两个词叠读。局部增益或变速的进出边界也要检查，不把词时间戳当作天然无杂音的切点。底噪变化先处理来源和相邻段电平，不用大量静音或强降噪掩盖。
3. **音乐与音效。** 连续讲述优先保留连续配乐，不能因为换图、字幕切换或 unit 变化而重启音乐。确需换曲、退出或循环时，选择合适乐句，设置可听辨的平滑包络；BGM 淡入淡出可从约 0.5–2 秒试起，按节奏和尾音调整。重叠曲目要控制叠加峰值，保留混响尾巴。核对 duck 的恢复是否造成抽吸感；不要给每个转场加 click/whoosh，也不要用音效遮盖技术杂音。检查实拍素材是否意外带入原声。
4. **保留时间关系。** 原录音和 TTS 缓存保持不变。修改落在生产程序或有来源记录的派生音频，记录边界时间、操作、输入/输出哈希及样本数。只做不改变时长与发音位置的包络处理时，核对后可保留时间戳、复用画面并重新混音封装；裁剪、重叠拼接、补停顿或变速改变了时间，则重新对齐受影响内容。正式合成保持连续音频母带，避免逐镜头独立有损编码人声再拼接造成接缝；局部样片也需检查最终编码结果。
5. **验收最终文件。** 听审全部实际音频编辑边界及配乐起止点，并检查章节切换；纯画面切换且音轨连续的区间可抽查，用户指出的位置全部复查。用正常播放音量核对最终 MP4，而非只看波形或听 WAV。出现疑点时局部 A/B 比较，再回到上下文判断。记录已听时间范围、使用文件、结果和未覆盖项，绑定最终 MP4 哈希；未实际听到的点保留 pending，已确认的杂音未解决则 audio 为 failed。LUFS、真峰值、无黑场和字幕覆盖通过均不能证明接缝干净。

**当前能力边界：** `audio_tracks.fade` 已用于附加音轨淡入淡出，局部强调处理已有短淡化；这不等于所有人声拼接点已平滑，也不等于已有自动爆音检测或接缝听审。上述规则是制作与验收要求，不是新增配置字段或已实现的自动修复功能。执行时先检查当前代码；缺少处理能力时按当次授权实现、验证，不能仅改 skill 就宣布杂音已消除。

### 脉冲杂音的证据与修复

1. 从用户时间点前后各 5–8 秒取实际 MP4 音频，保留原始片段；依次比较原始录音/合成单元、母带、配乐和混音，检查接缝、削波与短脉冲。没有接缝不代表没有 TTS 内部爆音；普通清辅音也不能只凭峰值当作噪声。
2. 已明确为咔哒、爆音时，可对人声副本使用保守脉冲插值；当前实现 adeclick threshold=4、window=40ms，禁止直接套到所有配乐打击乐。记录检测样本数、比例和方法，保留原始音色、正常呼吸和声母；若定位到配乐，单独替换/修复对应素材，不通过削弱整个人声解决。
3. 修复前后必须采样率、声道、样本数完全一致；校验前后片段、关键语句和正常非问题段，检查响度与真峰值。不要把算法检出的每个样本宣称为确认的杂音。
4. 从最终 MP4 再取问题点验证，不能只测中间 WAV。给出前后可播放片段；没有实际听到的主观项目保持 pending，不宣称“所有杂音已清除”。
