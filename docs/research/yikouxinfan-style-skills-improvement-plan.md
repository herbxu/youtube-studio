# 一口新饭样本对应的制作技能改进计划

2026-10-27。依据[特斯拉视频风格分析](yikouxinfan-tesla-video-style-analysis.md)、当前五个制作技能及相关生产代码制定。本次交付计划，尚未修改技能、生产程序、剧集或配置。

目标是让脚本、口播、视觉和声音共同推进观众的理解，同时保留本项目的财经杂志式摄影拼贴、证据材料和动态图解方向。优先修订现有规则与实例，保持技能入口简短，不新增一套平行的制作流程。

## 现状与实际缺口

| 方面 | 已有能力或规则 | 本次需要补充的决策 |
|---|---|---|
| 整片脚本 | narrative 的 question、changes、bridge；真实经历与证据边界；三类叙事方法 | 怎样解释一个未发生改变的个人选择；怎样及早交付核心答案并回收后文承诺 |
| 画面 | 对象持续、真实原文高亮、对象强调、词级锚点、短句停留 | 怎样按解释任务选择强调、局部展示或换景；怎样保持作者存在感 |
| 口播 | delivery、句群、读音、局部强调、最终听审 | 怎样让提问、犹豫、修正和收束与论证作用一致，而非统一加强情绪 |
| 音乐 | 可不选 BGM；素材筛选；cue、fade、duck；接缝检查 | 哪些段落需要声音变化，哪些保留干净口播；声音如何承接章节转折 |
| 质量 | 内容、声音、画面、工程、效率五维检查 | 怎样验证几个元素合起来没有抢夺注意力或改变结论强度 |

现有规则已较完整。重点是改进选择依据和交接，避免在五个入口重复增加同一批通用要求。

## 第一优先级 解释个人选择与组织整片节奏

修改 [youtube-write/SKILL.md](../../skills/youtube-write/SKILL.md) 与 [narrative.md](../../skills/youtube-write/references/narrative.md)，详细方法放在后者。

1. 增加可选的“个人选择解释”路径：外部期待或观众疑问 → 作者的实际目标与约束 → 替代方案的代价 → 选择及其适用边界。这适合“为什么我继续这样做”，不要求作者先犯错或发生观点转变，也不强制四个理由。
2. 为开头增加判断标准：观众能否知道矛盾是什么、为什么与自己有关、作者准备回答什么。较长论证可以先交付方向性答案，再逐步解释条件；不把答案全部留到结尾，不规定固定秒数。
3. 使用现有章节 question、changes、bridge 检查递进。每一章应推进认识或补充必要条件；重复故事如果不增加作用，应合并。对特别长的章节检查是否混入多个问题，不要求章节等长。
4. 检查后文承诺是否回收。只追踪影响主线的“稍后解释”，不要为了制造悬念反复延期。回收情况在人工审稿说明中记录，暂不增加必填字段或声称 CLI 会自动检查。
5. 将个人故事的评价落在功能上：它是在提出问题、展示约束、检验判断，还是说明边界。继续使用已有来源与 argument.basis，不另存故事正文；没有真实经历时，用明确标识的假设或原始证据替代。

**验收：** 用普通机制题、真实个人选择题分别进行桌面推演，确认不会机械生成同一种结构；检查开头承诺、章节衔接和结尾回应是否一致。使用虚构且明确标识的最小材料即可，不自动读取新个人资料或制作历史剧集。

## 第一优先级 同一视觉结构中的注意力组织

修改 [youtube-visuals/SKILL.md](../../skills/youtube-visuals/SKILL.md)、[visuals.md](../../skills/youtube-visuals/references/visuals.md)，在 [explain-scenes.md](../../skills/youtube-visuals/references/explain-scenes.md) 增加对应现有能力的简短例子。

- 先判断本段需要观众辨认哪个关系或变化，再选择保持、强调、局部展示或换景。高亮用于当前解释的重点；真正换对象、换证据或换尺度时再考虑换景。
- 增加一个可落地的例子：同一份公告局部先显示融资金额，再高亮用途；随后用独立对象图解释用途与回报之间还缺哪些条件。证据与解释各自承担职责，不能用重绘文字冒充原公告。
- 区分“回到同一个问题”和“恢复同一场景状态”。当前 object_scene 要求同一 scene_id 连续，不能直接照搬参考片中离开页面后又恢复动画状态的做法。
- 按本期输入设计作者存在感。有已授权的真人素材时，让表情、手势或实物承接个人立场；没有时，用真实录音、个人记录的必要节选和明确的第一人称判断承接。分屏、画中画等未核实能力不写成已实现功能。
- 增加局部可读性判据：关键论点不依赖观众阅读缩小的整页小字；必要条件与来源仍须可获得。手机尺寸检查关注理解任务，不以字号或截图数量代替判断。

**字段复用：** purpose 记录画面贡献；evidence.events.highlight 与 object_scene.events.emphasize 承接已有强调能力；delivery 记录讲话意图。不新增 attention、camera 或 arbitrary_highlight 等未实现字段。

**验收：** 桌面检查一段“同一对象连续解释”和一段“证据切换”，确认没有按 unit 强制换景、无条件推拉或整页讲义复制。实际观看体验留待下一次获授权的视频制作验证。

## 第二优先级 按叙事作用选择音乐和口播表达

由 [youtube-media/SKILL.md](../../skills/youtube-media/SKILL.md) 和 [media-contract.md](../../skills/youtube-media/references/media-contract.md) 负责选材意图；由 [youtube-voice/SKILL.md](../../skills/youtube-voice/SKILL.md)、[voice.md](../../skills/youtube-voice/references/voice.md) 和 [voice-profile.md](../../skills/youtube-voice/references/voice-profile.md) 负责表达、落点与混音。

| 段落任务 | 拟加入的选择依据 |
|---|---|
| 复杂机制、数字、限定条件 | 优先保证清楚；可以不配乐，或减少背景声干扰 |
| 个人经历与反省 | 判断音乐是否支持当事人的表达，避免把不确定判断渲染成确定结论 |
| 章节过渡 | 可让声音在过渡句开始、跨过视觉切换，具体位置由实测口播与听感决定 |
| 结尾回收 | 允许声音帮助收束，也允许保持干净口播；不默认煽情或上扬 |

这些是选择标准，不是每章必须选择一个音乐标签。使用现有 media-plan 的 purpose、cue、mood、density 和检查记录，填写作用、进入与退出依据；已决定无配乐的段落可在现有规划说明中注明，不制造没有资产的 BGM 请求。

将 voice.md 中“连续讲述优先保留连续配乐”明确限定为：**已经选用同一段配乐时，不因换图或 unit 边界重启；需要结束或回到干净口播时允许退出。** 这样避免把连续性误解为全片铺音乐。

根据代码，audio_tracks 在所属单元 cue 定位后转为全片时间，duration 可以延续到后续单元，但不得超出素材或成片。要提前于下一章进入，可选择上一单元实际说出的过渡句作为锚点；无需先开发负 offset。此处为代码路径核对，不代表新音轨已听审或已渲染验证。

不规定固定提前十秒、不照搬约 315 字／分钟或样本响度，也不预设钢琴、Lo-fi 等曲风。样本只支持局部声音变化与章节的关系，未完成的主观听审不能转化为选曲事实。

口播规则补充一个对照：同一句“但这不代表……”在解释边界时应接续前文，不必一律增加重音、增益或停顿。delivery 描述实际意图；现有局部音频处理只用于合适的片段，不能代替自然演绎。

**验收：** 检查无 BGM、音乐跨单元、章节转段三个规划案例；确认不会自动下载、合成、循环音乐或更换音色。最终音乐是否合适只能在真实混音中听审。

## 第二优先级 增加音画配合的质量判断

修改 [youtube-produce/SKILL.md](../../skills/youtube-produce/SKILL.md) 和 [quality.md](../../skills/youtube-produce/references/quality.md)。沿用现有五维 review.json，不新增笼统分数或第六套审核流程。

保留已有“只听声音能否理解、画面是否增加理解”的检查，补充正常音画合看：

- 反问、解释、证据和结论在声画上是否对应；有没有高亮尚未解释的结论，或音乐把有条件的判断推成确定承诺。
- 对关键转折检查完整上下文，确认章节标题、声音变化和人物/图解切换能帮助重新定位，不机械同时堆叠。
- 观众需要读数字、看变化、理解旁白时，画面是否提供足够的观察与停留空间；不以统一切镜频率衡量节奏。

问题按主责记录到 content、audio 或 visual 的 evidence，并引用同一时间范围；不要复制三份相同待办。接缝、发音、混音和连续观看继续分别记录，未实际完成的项目保持 pending。

**验收：** 能区分“单独音频正确、单独画面正确，但合在一起难以理解”的情况，并明确退回写作、声音或视觉中的哪一步。

## 修改顺序与交付边界

1. 先改 narrative.md 和 visuals.md，确定表达与注意力组织方法，再补必要入口链接。
2. 修改音乐选材与声音规则，替换可能引起误读的表述，保持规则各归一处。
3. 更新质量与交接，沿用当前字段和文件职责；authoring.md 只在确有澄清必要时调整，不新增运行参数。
4. 检查五个技能的 frontmatter、相对链接、触发范围、重复和矛盾；运行 skill-creator 的 quick_validate。用上述桌面案例检验决策，不把文档校验称为视频效果验证。
5. 交付变更清单与未验证项。纯技能修改不运行 TTS、素材下载、识别、渲染或发布，也不自动提交 Git。

第一轮仅涉及技能文档，默认不修改 src、config 或历史剧集。完整分析留在研究报告，技能只保留会改变制作决策的规则和短例子。

后续实际制作若确实需要“对象场景离开后恢复”“独立淡入淡出时长”“结束词锚点”或将声音事件纳入自动分镜阅读稿，再单独安排程序扩展及对应测试。当前高亮、对象强调、章节导航和音轨混合均已有实现，无需为落实本计划重新开发一套。

本计划的完成标准是技能变得更准确、可执行、易于交接。实际视频是否更好，需要在下一次获授权的成片上，用完整论证选段、最终混音和连续观看来验证。
