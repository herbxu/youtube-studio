# trade → youtube 自动制作流程审查与改进计划

日期：2026-10-25。范围：当前工作区代码、技能契约、剧集输入与交付记录、trade 当前目录和研究，以及小A、思维咖啡、一口新饭的既有样本分析。此文是实施计划，不代表下述新增能力已经完成。

> 2026-10-27 范围调整：用户要求先在现有 skills 中融合 trade，撤销腾讯案例，不新增或沿用主题做测试，待用户提供新主题后再验证。本轮未验收的程序、配置、测试及试点接入已收回；下文工程阶段保留为后续候选计划，不代表正在执行或已实现。当前工作约定见 [trade 研究交接](../../skills/youtube-write/references/trade-context.md)。

## 一、结论与职责

当前已经有较完整的自动生产执行器，能够把准备好的脚本、声音和素材变成可检查的本地视频。主要缺口在上游研究交接、把论证变成视觉解释的编导过程，以及最终的内容和体验审查。

建议目标是：常规步骤连续自动执行，已确定的作者判断和资料可以追溯；只有缺证据、关键声音差异、素材或验收失败等具体例外进入待办。减少重复确认，同时不让“命令运行成功”承担它没有验证的含义。

分工如下：

| 仓库 | 负责 | 交给下游的内容 |
|---|---|---|
| raw | 原始资料获取、财报证据核验与版本管理 | 可追溯事实、原 PDF、页码、期间与口径 |
| trade | 投资经验、思维方法、正式原则、公司研究及复盘 | 作者判断、真实经历、证据引用、假设、反证与失效条件 |
| youtube | 观众问题、叙事、口播、声音、素材、图解、渲染与交付 | 可播放视频、字幕、来源说明、质量状态和制作记录 |

youtube 只读获取 trade 的研究输入。制作中发现矛盾，记录反馈和需要补充的证据，不为了增强戏剧性反向改写投资原则。trade 的 `05-知识体系` 是学习资料，可用于有归属的读书讨论，不能自动变成作者正式信念或公司研究依据；历史复盘也不能被写成当前持仓。

## 二、当前自动化到哪一步

实际程序链路：`script → voice → align → assets → compose → render → verify`。Agent 依据 skills 做研究、写稿、选素材和审阅；单独调用程序时不会自动执行整套 skills。

| 环节 | 当前事实 | 仍需要什么 |
|---|---|---|
| 选题与研究 | 没有 trade 导入阶段 | Agent 找材料、区分当前判断与历史想法、形成 brief |
| 写稿 | 无 script 时，用 brief 与 authoring.md 调模型；有 script 时沿用 | 自动写稿调用未读取 trade、完整写作技能或 narrative.md 正文 |
| 论证检查 | 有 editorial、argument、narrative 与待审报告 | 部分字段仍可缺省；报告提示不会阻止进入付费配音 |
| 配音 | 录音导入、正式 TTS、缓存、标准化、局部强调和母带已实现 | 音色、错读、接缝和整段理解需有审查证据 |
| 对齐 | 实际 ASR/声学对齐，支持导入 words、关键术语与时间范围检查 | 导入音频与 words 未完整绑定；独立识别差异尚未形成关键差异处理闭环 |
| 素材 | 本地素材冻结、实拍裁切、必要插画生成、素材索引已有 | 搜索、候选比较、许可及试听由 Agent 执行，素材计划尚未成为统一执行队列 |
| 编排 | 原文高亮、有限连续对象、专用竞争场景、数量机制等已有 | 仍需编导判断画面任务；不能任意返回旧场景继续变化 |
| 渲染与恢复 | 缓存、哈希、单剧集锁、不确定付费请求阻断、增量片段和音画分离已有 | 时间变化仍可能影响后续片段，需要继续量化返工范围 |
| 验收 | 尺寸、时长、响度、峰值、黑场与抽帧；review 绑定视频和输入 | 内容支持度、连续画面、声音自然度仍可能 pending；分散状态需要统一展示 |

已经具备的缓存、恢复、锁、音轨混合和审阅绑定应保留，不重复重建。

### 本次读取的剧集状态

- 未改动正在制作的脚本、缓存、锁、运行状态或输出。本次是时点审查，不是对并行制作最终结果的判定。

## 三、优先解决的实际问题

### 1. 上游研究修正不会传到视频

历史稿与后续研究可能对同一事实有不同解释。制作时需要核对采用的研究版本，并把变化定位到受影响主张；本计划不再指定旧公司案例作为测试输入。

目前来源 ID 有效就能满足一部分结构检查，没有源版本 → 主张 → 口播 → 镜头的影响映射。系统可能把已经过时的判断稳定地配音、渲染出来。

### 2. Agent 写作与程序写作获得的规则不同

写作技能要求认知递进、反例、作者立场和来源，但 draft 只加载 authoring.md。该文件里的相对链接不会自动变成模型已阅读的内容。新稿是否真正获得研究材料、叙事规则与模板边界，取决于启动方式。

应统一生成写作上下文，而不是继续增加只有 Agent 会读的说明文件。来源存在性、字段齐全可由程序判定；论点是否被支持仍需内容审查，不能混为一项分数。

### 3. 编导目前容易受模板推动

有 purpose 和 argument 字段不意味着画面解释了机制。《竞争优势》实际完整脚本仍以插画和短概念图为主；街区样片的改善尚不能代表所有正式主题。

最缺的是“本章哪个对象持续存在、发生了什么变化、观众由此改变什么判断”的规划。缺资料时不应自动用插画填空，缺动作时也不应只增加文字入场。

### 4. 连续对象还不能实现一口新饭式反复返回

object_scene 当前要求同一 scene_id 的镜头相邻，最多六个对象，连线后不能继续移动。它可以跨连续口播单元，却不能实现“模型 → 公告/个人故事 → 返回模型继续修正”的完整结构。

最值得扩展的是场景状态保存与返回，其次是同一对象的受约束数值/状态更新。不要把返回场景简化成复制一份新对象后从头播放。

### 5. 声音正确性仍有两个薄弱点

导入工具已写 audio_sha256，但 align 消费导入 words 时未核对它与实际音频的来源关系。换录音但沿用旧 words，可能误用旧动作锚点。应区分原录音、标准化音频及实际剪辑关系，任何改变时间的处理都要重新配对。

强制对齐会按参考正文寻找位置，覆盖率高不能证明数字或否定词读对；虽然独立 ASR 差异已保留，却还没有按“影响含义的差异”处理。应把疑点切成可定位的声音片段，判断是识别错误还是实际错读，不能让受约束文本自行证明自己正确。

### 6. 制作状态分散，限制无人值守推进

脚本审读、素材候选、素材审查、声音差异、渲染和质量分布在不同文件。一个任务缺少素材还是缺少听审，需要重新阅读多个产物。

已有 quality 区分机器通过与人工审阅，但顶层执行成功、旧交付、新输入和实际待办还应放到同一份摘要。自动化需要清楚下一步可做什么，不只记录上一条命令成功了。

## 四、将博主风格变成制作步骤

| 参考能力 | 自动化中应增加的具体工作 | 对应主题 |
|---|---|---|
| 小A：一个变量解释机制 | 每个解释段确定对象、初始条件、变化、结果和反例；按真实口播安排动作 | 竞争优势、融资、估值 |
| 思维咖啡：让观众先想到自己 | 从 trade 的真实处境提取一个自问，保留改变判断的例子，删去重复说明 | 长期持有、梯子、投资理念 |
| 一口新饭：个人困惑与持续修正 | 提取作者原来的判断、反对意见、后来为何改变；核心图形能返回并继续变化 | 现金储备、持有、资本配置 |
| 三者共有：声音与画面分工 | 旁白独立可懂；证据支持事实；动画解释关系；短文字只突出必要判断 | 全部主题 |

这些是内容选择规则，不是强制镜头比例、语速、色板或片长。真人出镜是可选输入；没有出镜时，真实复盘、稳定声音和明确立场仍能建立作者感。当前 footage 会剥离源音轨，不能直接声称已支持一口新饭那种保留采访原声的完整引用流程。

## 五、目标流程与最小交接契约

建议流程：

`读取 trade 当前研究 → 冻结本期研究包 → 形成问题与论证 → 编导和素材需求 → 配音前检查 → 配音/录音 → 对齐 → 素材冻结 → 编排预览 → 增量渲染 → 分项审查与交付`

前几步可以由 Agent 连续执行，结构检查与生产由程序负责。动作、秒数仍来自真实语音对齐；预估时长只能用于选材规划，不能冒充最终时间戳。

### 研究包：存输入，不另存第二份脚本

建议新增 `source/research/research-package.json`，这是未来接口，不是当前可执行格式。最少包含：

- 主问题和研究截至日期。
- 作者正式立场、真实经历、学习观点分别归类，记录源文件、段落、日期和哈希。
- 支持每项事实的 raw 证据引用、原 PDF 哈希及物理页码；财务值注明期间、币种、单位、口径及计算来源。
- trade 的解释、假设、最强反证、仍未知的部分与失效条件。
- 哪些节选可用于本期公开表达，哪些仅作背景；默认不把完整账户信息作为写稿输入。
- 来源版本及 source → claim → unit → shot 的对应关系。

脚本继续只编辑 `script.json`。narrative、argument、claims 和 shots 继续复用，不建立相互竞争的“导演稿”和“最终稿”。数据缺口由 raw/trade 上游处理，youtube 不通过搜索摘要补财报数字。

上游改动时比较哈希并列出受影响主张，不自动覆盖已确认立场。历史成片保留原研究时点；新制作或重新交付要检查变化是否影响当前表述。哈希变化只是复查触发器，不能自动等同于研究结论改变。

## 六、实施阶段与验收

| 阶段 | 具体改动 | 完成标准 |
|---|---|---|
| P0-A：研究接口 | 在 youtube 增加只读 trade 适配与研究包；来源类型和原始事实保留区别；生成影响映射 | 用户新主题中采用的研究版本可追溯到具体句子；学习观点不会自动变成作者原则；本地路径失效被发现 |
| P0-B：配音前检查 | 统一 Agent/程序写作输入；新稿要求主问题、章节、依据和条件；关键来源缺失或矛盾形成可处理项 | 缺关键证据时不会先产生整期付费配音；正常材料无需逐环重新确认；历史稿仍可查阅，不批量重写 |
| P1-A：声音配对 | 核对音频、标准化产物和 words 的关联；关键 ASR 差异进入处理队列 | 替换音频却保留旧时间戳时被拒绝；改错一个数字只重做相关声音及受影响时间线 |
| P1-B：统一制作任务 | 将素材计划、已获取/已核对/已绑定、声音疑点和质量待办接到现有状态摘要 | 每项缺口有所属镜头、原因和下一步；程序能区分旧成片与当前待完成输入 |
| P2：连续模型演进 | 增加保存/返回场景；必要的对象状态变化；证据插入后返回同一模型 | 正向与倒序定位一致，返回时对象身份和状态正确；局部修改仅使相关片段失效 |
| P3：整期试运行与复用 | 以一个主题贯通研究到成片；用不同类型第二期检查是否泛化；记录质量、成本与返工 | 一期可追溯到研究版本，实际声音和画面审查有证据；下一期不依赖重写专用整套逻辑 |

P0-A 是内容层依赖；P0-B 和 P1-A 都应在扩大批量配音前完成。P1-B 可接续现有素材库，不必先开发庞大的在线素材平台。P2 在前面链路稳定后做，避免把内容问题制作得更精致。实际工程量取决于适配范围，先用一家公司、一条经历和一个解释场景验证，不承诺未经试做的工期。

### 例外处理与自动化边界

正常步骤复用已有授权连续执行。客观问题先自动修复，例如按已验证迁移关系恢复本地引用、修正非关键排版、重建缓存；找不到可靠对应关系的来源进入待办，不猜测替换。内容缺证据回到研究输入，声音有疑点定位片段，缺合适素材记录替代方案，付费请求结果不确定沿用已有阻断机制。

规则检查、Agent 看图/播放/听审和人工结论分别记录。没有实际执行的听审不能被自动填成通过。新增审核器应提供问题位置、证据和修复建议；不能用一个“风格分数”直接覆盖现有质量记录。自动发布不属于本计划，终点仍是本地交付。

## 七、后续使用用户提供的新主题验证

当前仅检查技能格式、引用与职责一致性。已撤销腾讯、长期持有的本轮试点输入，不继续选择历史主题或新增样片。

收到用户新主题后，先按技能完成相关研究的只读选取和叙事设计，再依据实际制作缺口决定是否需要程序扩展。真实经历、来源追溯、画面解释和返工效率均在该主题的授权范围内验证，不预先要求额外测试剧集。

## 八、衡量改善的指标

第一期先建立基线，不根据源码数量估算“自动化百分比”。记录：

- 进入脚本的关键事实中，能够回到具体原始证据的比例；所有第一人称经历可回到真实记录。
- 缺证据或论证冲突在配音前发现的数量，以及配音后因此返工的数量。
- 常规制作需要人为补充上下文的次数、待办种类和等待原因。
- 本期实际 TTS/生图请求数、成本（服务提供时）、复用情况和不确定请求数。
- 改一句口播、换一张图、换 BGM 三种操作分别重做多少资产、耗时多少。
- 关键数字/否定词未处理差异、字幕安全区问题、对象错误重置与未完成审查项。
- 内容、声音、画面、工程、效率五项质量是否绑定当前版本；解释段有没有展示中间机制。

不把多镜头、多动画、固定换景频率或机器通过率当成观看效果的替代指标。
